## 二、老师反馈与建议

老师对我们的进展表示认可，并针对下一步方向给出了具体指导，归纳如下：

### 老师重点推荐的两个方向

**1. 医疗数据处理场景**

老师建议我们可以考虑把项目聚焦到一个具体场景上——医疗数据处理。这样既有应用价值，也能让项目更有目标感，避免泛泛地"玩模型"。

**2. Agent 技术与 RAG**

老师建议关注 Agent 和 RAG（检索增强生成）方向。这是当前大模型应用的主流趋势，作为学习项目很有前瞻性，可以作为后续深入的方向。

### 技术实现层面的建议

| 方面         | 老师建议                                    | 对应组别      |
| ---------- | --------------------------------------- | --------- |
| Docker 容器化 | 用 Docker 打包部署环境，方便团队统一开发环境，也便于最终展示      | 后端组       |
| 模型切换功能     | 前端支持切换不同模型，展示对比效果                       | 前端组 + 模型组 |
| 模型输出对比     | 前端能同时展示多个模型/参数下的生成结果，方便直观比较             | 前端组       |
| 流式输出       | 接入流式输入/输出，让用户能看到文字逐字生成，体验更好             | 后端组       |
| 接入线上 API   | 除了本地 Ollama，可以接入线上 API，并保留上下文（多轮对话）     | 后端组 + 模型组 |
| 部署到 GitHub | 最终成果部署到 GitHub Pages 或 GitHub 上，方便展示和分享 | 全组        |
| 意图识别       | 微调后要检验模型是否保持了其他能力不变，不能只看目标任务            | 模型组 + 评估组 |
| 评测数据集      | 评测数据集范围要广，用来检验微调对其他领域是否有负面影响            | 评估组 + 数据组 |

### 关于"深入方向"的建议

老师说项目可以在以下方面适当深入，不必全部做，但值得去了解和尝试：
- **大模型评测**：不只是 BLEU/PPL，了解业界主流评测方法
- **场景化应用**：找一个具体场景（如医疗）深挖
- **找论文分享**：团队成员可以定期找相关论文互相分享，提升学术视野
