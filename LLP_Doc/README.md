# 二、About Vibe Coding
### 1. Core：从“创作者”转变为“审查者”

在 Vibe Coding 模式下，代码不是写出来的，而是“引导”出来的。

- **Prompt** 即规格说明书：模型组和后端组在让 AI 生成代码前，必须先理清逻辑。如果 Prompt 模糊，生成的代码就会像“屎山”。
    
- **强制性的 Code Review**：因为代码是 AI 生成的，我们可能并不完全理解其内部逻辑。要求每组在 `git commit` 前，必须由另一名组员解释一遍代码的关键逻辑。
    
- **模块化隔离**：不要让 AI 一次性生成整个项目。通过 `flask_hello.py` 或 `streamlit_hello.py` 这种小文件进行增量开发。

---

### 2. 针对各组的 Vibe 指南

- **模型组 (M1, M2)**：利用 AI 快速生成 `lora_config.py` 的模板，但必须手动核对 `target_modules`（目标模块）是否与你们下载的小语言模型（如 TinyLLaMA）匹配。AI 经常会在模型层名称上产生幻觉。
    
- **前端组 (F1, F2)**：Streamlit 非常适合 Vibe Coding。你们可以描述 UI 布局，让 AI 快速产出 `input_output_demo.py`。注意保持 UI 风格的统一，避免 AI 每一页都给你们生成不同的配色。
    
- **评估组 (E1, E2)**：BLEU 和 PPL 的计算逻辑很固定，非常适合 AI 生成。但要注意数据集格式的对齐，确保 AI 生成的 `bleu_test.py` 能正确读取 `cleaned_dataset.json`。

---

### 3. 注意事项 (Red Flags)

- **版本失控风险**：AI 有时会为了解决一个小 Bug 而重构整个文件的逻辑。**必须严守 Git 规范**。在尝试大规模 AI 改写前，先开一个新分支（Branch），防止把跑通的 Demo 改废了。
    
- **忽略报错底层逻辑**：当程序报错时，不要只是把错误甩回给 AI 让它修复。如果团队中没有人理解为什么报错，到了第 7-8 周前后端联调时，项目会彻底崩盘。
    
- **文档缺失**：Vibe Coding 速度快，人容易变懒。要求文档组 (T1) 强制记录 AI 解决的关键问题，否则项目最后连 PPT 都写不出技术深度。

---

### 4. 工具链配合

- **使用环境变量**：不要让 AI 把 API Key 或本地路径硬编码在代码里。
    
- **保持上下文清洁**：给 AI 提供上下文时，只给相关的 `.py` 文件。给得越多，AI 越容易胡言乱语。

**总结：** Vibe Coding 是加速器，但 **Git** 和 **开发者文档** 是刹车片。没有刹车，跑得越快，撞得越惨。

# 三、关于B组
### 1. 明确分工与协同

建议将后端任务按“接口”与“业务逻辑”进行拆分，避免两人同时修改同一个文件导致 Git 冲突：

- **B1：API gateway 与 外部集成**
    
    - 负责 Flask/FastAPI 的路由设计。
        
    - 负责前端（F 组）与后端接口的联调测试。
        
- **B2：模型服务与数据流处理**
    
    - 负责将模型组（M 组）的推理逻辑封装为可调用的类或函数。
        
    - 负责处理数据组（D 组）产出的 JSON 数据读取与持久化。

### 2. 双人对齐 (Vibe Sync)

在 Vibe Coding 中，代码生成速度极快，两人协作最怕“你生成的逻辑我不懂”。

- **接口统一**：两人在写代码前，先共同商定 API 的输入输出格式（例如：`{"prompt": str, "temperature": float}`），并记录在开发者文档中。
    
- **交叉评审**：B1 让 AI 生成的代码，由 B2 负责阅读并添加注释；反之亦然。这能确保代码不是只有 AI 能看懂。
### 3. 技术方案优化（理想条件下）

如果时间充足，可以尝试更专业的架构：

- **异步任务处理**：大模型生成文本较慢，一个人负责研究如何使用异步（如 Python 的 `asyncio`）来防止请求超时。
    
- **环境一致性**：一个人负责维护 `requirements.txt` 或 Docker 环境，确保全组 11 人的 Python 环境完全统一。
### 4. 阶段产出调整

在Vibe Coding加持下，后端组在第一阶段（前两周）的产出可以更丰富：

- **Day 2**：产出 `flask_hello.py`（基础接口）。
    
- **Day 6**：产出 `api_frontend_test.py`（前后端联调脚本）。
    
- **新增**：两人协作产出 `api_docs.md`（接口说明文档），供前端组参考。
